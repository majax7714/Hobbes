## Result, first

**T made no edit at all on the two-run pair for 5 of 8 keys, both runs** (`ed65b65095eb`, `8d1f98c7967e`,
`50493dbe1f75`, `6eaad039603a`, `d22371873bd8` — every one `empty-diff`, T's own verdict class for a diff with
no hunks). On the 3 keys pass can be read, **T is 0/3 in both runs** — every row is `empty-diff`. **O is 2/3**
(`ed65b65095eb` pass, `8d1f98c7967e` pass, `d22371873bd8` fail — a genuine regression, `TestTranslateExtend`,
confirmed not a scoring artifact). **The floor is not established at A2 here either, and by a wider margin than
round 1**: T's pass rate (0.0) is not just below O's (0.667) but below round 1's own T (0.20–0.25) — the extra
holes from live co-change (§ above) and the tighter N = 7 budget did not help T act; on these shapes it mostly
did not act at all.

**The one place T did edit** (3 of 8 keys per run — `87d96295d65a`, `a82bc53d895f`, `c98e5e0d27b3`, all either
`new-symbol` shape with a declare-hole, or otherwise the model chose to write a body) shows the **build-row
repair working exactly as designed**: on `87d96295d65a`, the model invented `utils.Alphanumeric`
(near-miss for `AlphaNumeric`); grounder v3 raised it `near-miss`/`invented`; the declaration repair fed back
the live `go build` error (`undefined: utils.Alphanumeric (but have AlphaNumeric)`) in one bounded exchange;
the repair closed the NULL and the build went from `build-fail` to build-clean in **both runs**. Run 1's
build-clean result reached no guarding test (`vacuous`); run 2's did, and the test **failed** (`fail`) — the
repair fixes the build, not necessarily the semantics. This is the one real signal of protocol v0.6's new
mechanism firing on a real key; no other key ever reached a build-fail state to exercise it (every other row
was either already build-clean or never edited at all — `empty-diff` never runs the build check, §2.4's own
rule: the build row spends no call but only runs on a placed declaration).

**G is clean** (0 NULLs of any class, either arm, across all 21 rows — because so little was written). **No
recall** on any row, either arm (all 8 keys post-cutoff, the scan ran anyway per §0b). Gold's own diagnostic
(`gold_tests`) never changed a verdict this run: it can only promote a `vacuous` row to `pass`, and no row that
would matter (on the 3 readable keys) was ever `vacuous` — every T row there was `empty-diff` (which `gold_tests`
cannot rescue, `harness.verify`'s own rule) and O's were `pass`/`pass`/`fail` outright.

## §5 — the reading selected

The design's own preregistered readings are written for **equal budget**; Max's amendment (§0b) keeps O's
30-turn/1M-token condition and binds N = 7 to T only, stated here plainly: **this is not an equal-budget
comparison.** Reading it anyway against §5's shapes: **T < O, at the wider (not equal) budget, with T's own
side showing it rarely acted at all** (10 of 16 T rows are `empty-diff` — no edit, not a wrong edit) rather than
"needed-fraction ≈ 1 but wrong" (§5's fourth bullet) or "the caps starved T" (§5's fifth bullet, H-s) — T had
budget to spare (0 budget cuts) and the touched symbol's full body was always in view (a single-symbol template
trivially renders the one thing needed). **The residual this round is T's own act-or-not decision, not a
template-visibility gap** — a new, sharper reading than round 1's "declared in the right world, not compiled":
here T mostly never got to "declared" at all. The one key where it did (`87d96295d65a`) shows the build-row
repair working end to end (build-fail → build-clean, both runs) — Hobbes's side of protocol v0.6 held up on the
one case that reached it; what it could not do was make the model choose to write code on the other 5–6 keys.

**Not selected:** "the socket buys cost, not outcome" (T ≈ O) — T is far below O, not near it. "Signatures move
'not compiled' into NULL classes" — moot this round, no row ever reached a NULL of those classes (0 references
needing arity/undeclared-type checks were ever written). "H-s, raise the caps" — budget was never the binding
constraint (0 cuts anywhere); raising N would not change a key where the model wrote nothing.

## §7 next step, as the design reads it

§7's fan-out (anchors removed, world thinned, language, model items) is gated on the floor holding; **it does
not hold here either.** The next step this round's own evidence points to is upstream of §7's list: **why
Haiku 4.5 answers "unchanged" to a BODY hole it was asked to fill**, on 5 of 8 keys, both runs, with budget to
spare — is it the hole's own wording, the sheer count of surrounding co-change/module-region holes (73–99 for

model limit at this size. That is a template/prompt question, not a protocol patch, and it is cheap to test on
the same 8 keys with no new spend (vary what surrounds the BODY hole, replay against the recorded exchanges'
absence — there is nothing to replay *from*, so it needs one new small T pass, not zero-spend replay). Held for
